# Feature: Host Admin Panel

The following plan should be complete, but validate documentation and codebase patterns before implementing.

Pay special attention to naming of existing utils, types, and models. Import from the right files.

## Feature Description

Build the Host's administrative dashboard that provides full control over the game: dealing cards, assigning the Scribe role, managing players, viewing all hands (admin visibility), forcing state changes, and displaying the shareable join link. The Host Admin is a persistent sidebar/panel accessible only to the Host throughout the game.

## User Story

As a Host (Facilitator)
I want to manage the deck and flow of the game without technical overhead
So that I can focus on guiding my friends through the story

## Problem Statement

The Host needs to perform numerous administrative actions during a Dialect game: dealing cards, assigning who is the Scribe, advancing ages, managing turn order, and troubleshooting issues. Without a centralized admin interface, the Host would need to use developer tools or separate commands, breaking the flow of the game.

## Solution Statement

Create a `HostAdmin` panel component that is always accessible to the Host (collapsible sidebar). It provides buttons and controls for all administrative actions, a view of all player hands, the action log, and the "Copy Join Link" button that shares the Host's local IP address.

## NOTES

- **Host IP detection:** The server detects the local IP via `os.networkInterfaces()` and provides it to the client (either in the initial state or via a `/api/network-info` endpoint). This is what the "Copy Join Link" button uses.
- **Admin action validation:** Every admin action is validated server-side. The client-side `useIsHost()` check is for UI gating only — the server independently verifies the sender is the Host before processing any admin action.
- **Scribe permissions:** The Scribe gets access to the Word Building keyboard (Feature #9) and dictionary editing. The Host always has these permissions too (Super-Admin). This is enforced by checking `roles.host || roles.scribe` on relevant actions.
